Shallow copy and Deep copy

The difference comes down to how objects are copied, especially when nested mutable objects (like lists inside lists) are involved.

Normal Assignment (=)
a = [10, 20, 30]
b = a

Memory:

a ─────┐
       │
       ▼
   [10, 20, 30]
       ▲
       │
b ─────┘

Both variables point to the same object.

b[0] = 100

print(a)
print(b)

Output
[100, 20, 30]
[100, 20, 30]


Shallow Copy
A shallow copy creates a new outer object, but the nested objects are shared.

Example:
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)

Memory:

a ─────► +----------------+
          |   ●     ●     |
          +---|-----|-----+
              |     |
              ▼     ▼
            [1,2] [3,4]

b ─────► +----------------+
          |   ●     ●     |
          +---|-----|-----+
              |     |
              └─────┘

Notice:
Outer list is new.
Inner lists are shared.

Check IDs:
print(id(a) == id(b))

Output
False

Different outer lists.

Now check:
print(id(a[0]) == id(b[0]))

Output
True

Same inner list.

Modify an inner list
b[0][0] = 100

print(a)
print(b)

Output
[[100, 2], [3, 4]]
[[100, 2], [3, 4]]

Both changed because the inner list is shared.

Modify only the outer list
b.append([5, 6])

print(a)
print(b)

Output
[[1,2],[3,4]]

[[1,2],[3,4],[5,6]]

Only b changes because the outer list is separate.


Deep Copy

Deep copy copies everything recursively.

import copy
a = [[1,2],[3,4]]
b = copy.deepcopy(a)

Memory

a ─────► Outer List
             │
        ┌────┴────┐
        ▼         ▼
      [1,2]     [3,4]

b ─────► New Outer List
             │
        ┌────┴────┐
        ▼         ▼
      [1,2]     [3,4]

Nothing is shared.

Modify inner list:

b[0][0] = 100

print(a)
print(b)

Output
[[1,2],[3,4]]
[[100,2],[3,4]]

Original remains unchanged.

How to create them
Shallow Copy
import copy

b = copy.copy(a)
or
b = a.copy()
or
b = a[:]

(These work as shallow copies for lists.)

Deep Copy
import copy

b = copy.deepcopy(a)


Quick Comparison
Feature	Shallow Copy	Deep Copy
Outer object	New	New
Nested objects	Shared	New copies
Changes to nested objects affect original?	✅ Yes	❌ No
Function	copy.copy()	copy.deepcopy()

Example to Remember
import copy

a = [[1,2],[3,4]]

b = copy.copy(a)
c = copy.deepcopy(a)

b[0][0] = 100
c[1][1] = 200

print(a)
print(b)
print(c)

Output
a = [[100, 2], [3, 4]]
b = [[100, 2], [3, 4]]
c = [[1, 2], [3, 200]]

b shares the inner lists with a, so changing b[0][0] also changes a.
c is completely independent, so changing it does not affect a.


Interview Answer
Shallow copy creates a new outer object, but references to 
nested objects are copied. 
Therefore, nested mutable objects are shared between the original
 and the copy.
Deep copy creates a completely independent copy by recursively
 copying all nested objects. Changes to any part of the
  deep copy do not affect the original object.

Does 'is' work for comparing different data types?

Yes, is can be used to compare objects of different data types, but that's usually not useful.

Remember:

is compares object identity (Are these the exact same object in memory?)
== compares value equality (Do these objects have equal values?)
Example 1: Different data types
a = 10
b = "10"

print(a is b)
print(a == b)

Output:

False
False
is → False because an integer and a string are different objects.
== → False because their values (and types) are different.
Example 2
a = [1, 2]
b = (1, 2)

print(a is b)
print(a == b)

Output:

False
False

A list and a tuple are different objects and different types.

Example 3
a = None
b = None

print(a is b)

Output:

True

This is actually the recommended use of is.

Instead of:

if x == None:

write:

if x is None:

because None is a singleton object in Python.

Example 4
a = 10
b = 10.0

print(a == b)
print(a is b)

Output:

True
False

Explanation:

10 == 10.0 is True because Python considers them numerically equal.
10 is 10.0 is False because they are different objects and different types (int vs float).
Can is compare different data types?

Technically, yes. It will always check whether both variables refer to the same object, regardless of their types.

However, in practice, objects of different types are distinct objects, so is will almost always return False.

Interview Answer
is works with any Python objects, even if they have different data types.
 It checks whether both variables refer to the same object 
 in memory, not whether their values are equal.
  For value comparison, use ==; use is mainly for identity checks,
   especially with singletons like None.
